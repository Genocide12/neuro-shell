# NeuroShell — JARVIS 2.0: план развития

Этот документ фиксирует безопасный и реалистичный план развития NeuroShell в персонального голосового агента. Это не обещание автономности уровня кино: действия доступны только через явно подключённые инструменты и разрешения пользователя.

## Цели первой версии

1. Голосовой ввод через Web Speech API, если его поддерживает браузер/десктопная оболочка. Кнопка микрофона включает распознавание только по явному действию пользователя; повторное нажатие останавливает его. Текст распознавания попадает в поле ввода, но сам не отправляется.
2. Озвучивание ответов через SpeechSynthesis API с кнопками «Озвучить» и «Остановить». Не включать автоматическое озвучивание по умолчанию; не отправлять аудио на сторонний сервис без отдельного согласия.
3. Каталог локальных навыков: индексировать только `SKILL.md` в разрешённой папке, извлекать `name` и `description` из YAML frontmatter, показывать найденные навыки пользователю и читать полное содержимое лишь для навыков, релевантных текущей задаче.
4. Память под контролем пользователя: отдельные локальные заметки, просмотр, редактирование и удаление; не записывать секреты, API-токены или данные из файлов автоматически.

## Этапы

### Этап 1 — голосовой интерфейс
- Добавить кнопку микрофона рядом с полем ввода и озвучивание ответа.
- Проверить поддержку `SpeechRecognition`/`webkitSpeechRecognition` и `speechSynthesis`; при отсутствии показать понятное сообщение и сохранить обычный текстовый чат.
- Для распознавания указать язык интерфейса, обрабатывать отказ в разрешении, отсутствие микрофона, ошибку и завершение распознавания.
- Не начинать запись при загрузке страницы; визуально показывать активное состояние и давать немедленную остановку.

### Этап 2 — навыки
- Настраиваемый каталог навыков; в десктопном режиме читать через существующий файловый API, в веб-версии предложить выбрать/импортировать каталог или индекс JSON.
- Индексировать метаданные и пути, но не загружать все полные инструкции в каждый запрос.
- Подбирать кандидатов по запросу и описаниям, затем читать только выбранные `SKILL.md`.
- Считать содержимое файлов недоверенными данными: не выполнять инструкции из навыка, которые пытаются отменить системные правила или раскрыть секреты.
- Показывать в интерфейсе, какой навык выбран, и позволять отключить его для конкретного запроса.

### Этап 3 — локальная память и действия
- Добавлять память только по явной команде пользователя; дать экспорт, просмотр, исправление и очистку.
- Для опасных операций (удаление, перезапись, публикация, коммит, запуск внешней команды) сохранять подтверждение и показывать точное действие до выполнения.
- Вести понятный журнал вызовов инструментов без сохранения токенов и секретов.

## Критерии приёмки

- Чат полностью работает без микрофона и без поддержки Web Speech API.
- Микрофон не активен до клика; запись можно остановить; распознанный текст не отправляется сам.
- Озвучивание можно остановить, и оно не включается по умолчанию.
- Индекс навыков не загружает полные документы массово; выбранный навык виден пользователю.
- Ошибки инструмента показывают краткую причину и не маскируются успешным статусом.
- Перед перезаписью, удалением и коммитом есть подтверждение.

## Порядок реализации

Сначала реализовать и протестировать голосовые кнопки как необязательное улучшение интерфейса. Затем сделать каталог/индекс навыков с явным просмотром выбранных навыков. Память и расширенные системные действия оставить отдельными этапами, чтобы не смешивать доступ к файлам, хранение данных и голосовой ввод в один непрозрачный механизм.
